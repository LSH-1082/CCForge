# 팀 규칙 (`.claude/rules/`)

팀이 정한 규칙을 파일로 두는 곳이다. Orchestrator가 epic을 시작할 때 이 디렉터리를 읽는다. 파일이 없으면 해당 항목은 기본 동작을 따른다. 이 `README.md`는 규칙으로 읽지 않는다.

| 파일 | 내용 | 없을 때의 기본 |
|---|---|---|
| `branch-convention.md` | 브랜치 이름 규칙(형식, 유형 표기, 구분자, 길이 제한 등) | 첫 epic을 시작할 때 설문으로 한 번 묻고 답을 이 파일로 저장한다. 물을 수 없으면 `job_<날짜>_<일련번호>_<순번>_<slug>` |
| `git-convention.md` | 커밋 메시지 규칙 등 git 사용 규칙 | 커밋 메시지 `step <n>: <title>` |
| `coding-convention.md` (권장 이름) | 코딩 관례. 네이밍, 코드 스타일, 주석, 에러 처리 방식, 테스트 작성 방식, 그 언어·프레임워크에서 팀이 쓰는 패턴과 금지하는 패턴 | 없음. 에이전트는 기존 코드의 관례를 따른다 |
| 그 밖의 `*.md` | 팀의 다른 약속(리뷰 절차, 문서 작성 원칙, 릴리스 규칙 등) | 없음 |

- **파일 이름은 권장이다.** Orchestrator는 이 디렉터리의 `*.md`를 전부 읽고 내용으로 규칙을 찾는다. 브랜치 규칙이나 커밋 규칙이 `conventions.md` 같은 다른 이름의 파일이나 한 파일의 한 절에 있어도 그대로 따르며, 이름이 다르다고 없는 것으로 보지 않는다. 브랜치 규칙이 어디에도 없을 때만 설문으로 묻는다.
- 브랜치 이름과 커밋 메시지는 Orchestrator가 직접 따른다. job 디렉터리 이름은 브랜치 이름에서 `/`만 `_`로 바꾼 것이다.
- 그 밖의 규칙 파일은 경로를 모든 Task의 `task.constraints`에 넣어 에이전트가 읽고 따르게 한다.
- **코딩 관례는 여기에 적는다.** 특정 언어·프레임워크에 묶인 관례여도 팀이 정한 약속이므로 `rules/`의 몫이다. 파일을 주제별로 나눠도 된다(`coding-convention.md`, `testing-convention.md` 등).
- **무엇을 쓰는지와 어떻게 돌리는지는 여기에 두지 않는다.** 쓰는 언어·프레임워크, 테스트·빌드·린트 명령, 패키지 관리자는 저장소 루트의 `CLAUDE.md`에 적는다. 에이전트는 작업을 시작할 때 `CLAUDE.md`를 읽는다.
- 정본은 `protocols/workspace.md` 2절 "팀 규칙"과 "이름 규칙"이다.
